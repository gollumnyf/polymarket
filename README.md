# Pulse · Polymarket BTC 5M

本机运行的 BTC 五分钟 UP/DOWN 交易控制台。React + Vite 前端、Node.js 服务、SQLite 持久化，使用 Polymarket 官方 `@polymarket/client` SDK。

开发交接请先阅读 [项目交接文档（供开发者与 GPT 阅读）](docs/HANDOFF.md)，其中汇总当前功能、策略规则、编码风格、数据库与维护规范。

## 启动

新增 **区间突破模拟**：访问 `http://127.0.0.1:3100/range` 或左侧“区间突破模拟”，启动控制台也可输入 **6**。使用独立账户与 `data/range.sqlite`，新页面默认暂停。

**连续同向反买（默认启用，默认 3 场）**：直接读取连续已结束的市场场次结果，不读取订单胜负。每场只检查紧邻当前开盘之前的 N 场：从当前场次减 N×300 秒至减 300 秒，不能跳场、回退到更早片段或复用旧触发。全部 UP 则本场买 DOWN，全部 DOWN 则本场买 UP；每场重新核对。未官方结算时使用对应市场场次预计结果，官方最终结果优先；缺失、作废、不同向或官方修正导致条件不成立时，本场不启用反买，按常规区间规则判断。锁定只优先决定买入方向，仍须严格位于蓝色区域；触及边界暂停后，必须完成配置的连续收盘恢复确认。取消 0.50 触发价、0.55 成交上限及相对滑点限制；价格仍必须在 0 与 1 之间并符合 tick，执行深度、最小份额、手续费预算、资金限额、每场一单和开盘检测截止。模拟与实盘共用方向，资金与订单仍独立。开关及场数位于“高级参数与风险限额”；关闭后仅执行下述区间规则，配置版本改变后重新检查最近连续场次。

**共同入场条件：边界观望与蓝色区域恢复**：每侧边界比例默认 20%，可配置为 0（含）到 50%（不含），中部比例为 100% 减去两侧比例之和。价格进入配置的下侧或上侧边界区域（含阈值）以及区间外时暂停新单；连续已结束场次的收盘价严格回到中间区域（默认 60%），达到配置确认场数（默认 2 场），且下单前当前价格仍在中间区域后，按返回侧选向：下支撑侧向上回来买 UP，上压力侧向下回来买 DOWN；中部持续沿用，直至再次触及边界后按最近一侧重新选向。保留原资金序列，不重置首笔。突破计数采用固定参考上下界；蓝色区域和边界观望始终使用本场滚动支撑／压力，已确认突破也不能绕过观望；主策略保持运行、已有订单照常结算，每场一次和入场检测截止时间仍有效。RP-01 已移除，历史记录仅作审计保留。

**区间计算滞后分钟数**默认 **15 分钟**，可设 0–1440 分钟，按 5 分钟步进。计算上下界时，将完整历史窗口向前平移，排除最近的 K 线；例如当前场次 18:00 开盘、历史窗口 4 小时、滞后 15 分钟，则使用 13:45–17:45 的 48 根已结束 K 线。设为 0 恢复原窗口。只平移支撑/压力位计算；多数方向统计、连续突破确认和入场时间仍使用最新场次。实盘跟随模拟盘的此项设置；界面显示实际取样起止时间。迁移保留历史配置和订单原来的 0 分钟口径，当前配置新建 15 分钟版本并重算区间，历史不足时立即补取更早数据。

区间采用官方报价的已结束 **5 分钟实体 K 线**最高/最低价（不含影线），历史回看默认 **4 小时**，可设置 1–24 小时；每场结束重算，当前场价格不修改本场边界。无需往返次数、触及次数或宽度门槛。缺失场次立即补取官方起止价，不等待 30 秒轮询；按缺失场次去重、最多并发 8 个请求，每场返回后立即保存、重算和检查下单。官方起止价优先用于实体 K 线，逐秒行情断档只展示，不作为交易限制。补齐期间沿用同配置、同预言机的已存有效区间；首次尚无有效区间则等待接口返回，不使用残缺数据猜测边界。请求失败自动重试，不暂停策略。

区间基础方向按近 N 小时五分钟场次 UP/DOWN 多数选取，N 默认 2，可配置。统计直接读取市场场次数据，与是否下单、订单盈亏无关。官方最终结果优先；尚未结算的场次也计入，按该场官方起止价或同源末秒价格预测，最终结果发布后覆盖预测。须取得完整场次方向，同票取紧邻上一场的反方向，不跳到更早的已结算场次。基础方向和依据保存于 SQLite。信号区分“首次选向时的历史依据”和“当前上一场的官方/预计结果”；区间方向锁定规则保持不变。区间中部沿用基础方向；上下侧边界带（默认各 20%，可配置）暂停新单，返回中部按最近边界侧重新锁定方向（下侧 → UP，上侧 → DOWN），保留原资金序列。边界侧、触及时刻、恢复方向、恢复价和阈值独立保存到 SQLite，重启可恢复，订单和导出保留依据。

**突破须同时满足距离与连续收盘场数**。设置“突破距离 / 区间宽度”默认 **0.1%**，“连续突破确认场数”默认 **2 场**。参考宽度为上压力减下支撑；上穿线为压力＋宽度×比例，下破线为支撑－宽度×比例。首次实时价格严格越线时固定该组参考上下界。连续两个已结束场次收盘价严格超过同一条线、且确认时最新价仍越线，才确认上穿 UP 或下破 DOWN 状态；突破状态仍受边界观望限制，区间外不下单。等于突破线不算；同一场反复越线不重复计数；收盘未越线则重新计数；缺少收盘数据等待补齐。官方场次终止价优先，未取得时采用已存同源预测或末秒价格，确认前重新核对已计数价格。突破距离或场数不足时继续观望；首次位于中间且没有边界返回记录时，仍需完整场次方向数据；已记录边界返回时直接按返回侧选向。

历史区间每场仍重算，图中支撑、压力、蓝色区域及实际入场门槛统一使用本场滚动上下界。正在确认的突破参考上下界不随其移动，仅用于连续突破计数，防止新 K 线吸收突破后无法累计。确认后保留突破状态，回到旧参考区间或进入新滚动区间的蓝色区域时退出旧突破状态，按最新区间重新选向；已记录的边界暂停仍需完成连续收盘确认。基础方向、确认参考上下界、起始场次、最后确认场次、收盘价与来源、已确认场数均独立存储，重启后恢复；每单保留当时的确认依据。

每场开盘零延迟尝试，默认只检测到开盘后 **2 分钟**；设置中“开盘后检测时长”以分钟配置，后台按秒保存并严格执行（可设小数分钟，最小 1 秒、最大 299 秒）。截止前持续尝试，超时跳过本场。所选方向有效卖一价必须**严格小于 0.50**才触发，等于 0.50 不触发。触发后各档实际成交价允许上浮至配置的成交硬上限（默认 **0.55**，含上限），不再使用相对滑点百分比限制，并遵守 tick、最小份额、实际深度和含手续费预算。下单前再核对区间方向，每场最多买入一次；马丁、结束预测续投和错误自动重试沿用其他模拟盘。首次启动只读导入其他本地模拟盘已归档的同源官方行情及市场结果，不导入其资金或交易，不补造缺失报价。

区间数据按字段保存：`range_configs` 参数版本、`range_control` 当前配置与区间指针、`range_regimes` 支撑/压力及方向状态历史（含价位 K 线周期、回看小时数、起止时间、各侧价位来源、固定实际最高/最低价及锁定方向依据独立字段）、`range_market_prices` 按预言机窗口和场次保存官方起止价与获取时间（重启重建原始行情时不丢失）、`range_price_bars` 官方报价分段与断档证据、`range_votes` 场次统计及来源、`range_order_signals` 每单所用区间与观察价格（同票反向规则、下单时票数、上一场编号/方向/数据源均为独立字段）。交易、账户、日志继续使用独立的标准表，重启后保留区间及订单依据。

策略运行期间，接口错误、钱包检查失败、拒单、结算差异和非二元兑付都不会自动关闭策略。错误写入日志，后续检查自动重试；拒单后本场不重发，下一场继续；成交状态不明时持续核对，确认前不新增买入；余额、盘口或配置限额不允许成交时跳过本次检查，不越过约束。只有手动暂停或停止服务会关闭正在运行的策略。重启服务仍默认暂停，防止未经用户启动便恢复交易。

**历史兼容模块：官方同向模拟**（当前菜单已移除，旧 /momentum 地址重定向到实盘）。与原模拟盘、实盘的资金和交易记录独立，使用 `data/momentum.sqlite` 保存账户、配置、交易、日志和行情；`momentum_order_signals` 用独立字段保存每单最近两笔官方报价的时间、价格及预言机窗口。

该页面以 Polymarket 公布的本场初始价为准，零延迟等待首个符合条件的新鲜官方报价。本场涨跌方向与最近两笔价格的变动同向才买入；持平、冲突、超前、过期或缺少初始价均等待。最新报价必须晚于开盘，两笔时间递增且距今不超过 6 秒；前笔可为紧邻开盘前的新鲜报价。买入使用所选方向官方卖盘，逐档成交价格必须大于 0、小于 1 且 **≤ 0.50**，核对 tick、最小份额、滑点和实际深度，并在成交计算后再次核对信号。默认入场截止为开盘后 299 秒，可在设置中调整；每场最多一次，马丁资金序列及预测续投规则与原模拟盘一致。页面默认暂停，启动时保存首笔金额。

## 已实现的交易规则

1. 自动按 Unix 时间戳发现 `btc-updown-5m-{timestamp}` 当前场次，接收 Polymarket 实时 BTC 价格流，每秒检查交易并刷新订单簿；页面通过 SSE 更新。网络请求耗时可能使检查间隔更长。
2. 入场方向比较 **Polymarket 本场官方起始价** 与当前同源 Chainlink/TWAP 价格。当前价更高买 UP、更低买 DOWN；持平、行情不完整或数据过期时等待。页面明确标注参考源。图表涨跌金额和 UP/DOWN 信号以本场起始价为基准；上一场变动单独展示，收盘参考价尚未公布时使用同源的本场开盘边界，不将两场变动相加。
3. 首笔投入可自定义。默认 10 pUSD，投入按**含预估手续费的总预算**计算。输入金额后直接启动，会先保存输入金额，再启动；保存失败不会使用旧金额启动。输入框下显示实际生效的首笔金额与下一笔投入。盘口最小订单参数按份额检查（不是美元）。例如五份、价格 0.50、费率 0.07 时，含费约需 $2.59；金额过小会显示所需预算并等待，不会自动增大到用户未设定的金额。
4. 每场每种模式最多尝试一次买入：SQLite `UNIQUE(mode, round)`，覆盖页面刷新、多个标签页、服务重启和模拟账户重置。拒单也不会在本场再次尝试。
5. 失利后下一笔为首笔的 `2^连续失利次数` 倍。**任意一场方向获胜就恢复首笔金额**，不要求累计回本。这是用户确认的规则。
6. 持有到 Polymarket 官方 Data API 返回 `resolved` 与明确兑付比例。**不通过 Binance 涨跌、收盘最后一笔成交或盘口接近 1 来猜测结算。**
7. 上一场结束后，优先使用已获取的 Polymarket **该场次起始价和终止价**判断预计 UP/DOWN（终止价 ≥ 起始价预计 UP）。接口查询在后台进行；尚未拿到有效接口结果时，立即以该场起始价与该场**最后一秒内最后一个同源报价**预测，按预计失利翻倍、预计获胜复位推进下一场，不等待官方 `resolved`。采样必须属于 `[结束时间−1秒, 结束时间)`，来源与 TWAP 窗口一致，不使用更早的过期价、币安价或下一场报价。已采用的首次有效预测保留不覆盖，交易记录展示末秒来源和采样时间。上一单成交未确认，或接口及有效末秒证据均缺失时才等待；超过入场截止时间仍会跳过。
8. 官方兑付在后台按交易先后顺序入账，不阻塞新场入场，不提前把预计收益加到账户或可用余额。预测推进不会在实际结算时再重复翻倍/复位。风控保守计入全部未结订单成本，不把预计获胜视为已到账。预测与官方结果不一致、非二元兑付（例如各兑付 0.5）时记录差异，按官方兑付入账并继续运行；非二元兑付不虚构胜负，保留连败序列。

模拟盘与实盘的资金、订单状态、加倍序列、盈亏统计和参数相互独立。

未买入记录会明确区分卖一超过最高买价、最高买价限制可成交数量、滑点限制可成交数量、全部卖盘数量不足及预算达不到最小份额，附实际卖价、有效限价、可买份额、含费可成交预算和差额。行情缺失、请求失败、场次不匹配、采样过期、方向不一致和超过入场截止分别记录，不用合并原因代替诊断。每次拦截的配置、信号、时间及相关盘口逐档写入 SQLite；同一场相同原因的运行日志最多每 30 秒重复一次，原因变化立即记录。历史浮层可查看未参与场次的最近原因；`GET /api/:mode/entry-block/:round` 可读取该场最新依据及盘口，截止记录同时附带窗口内最近检查的依据。旧版没有保存的盘口不补造，标注依据不完整。

策略设置的“**入场方向规则**”使用下拉框，模拟盘与实盘分别保存。四种模式全部遵守配置的开盘后入场延迟，只有设置为 0 秒才从开盘开始检查：

- **不跟随上一场方向**：延迟到达后，按本场起始价与当前同源价格判断，上涨买 UP、下跌买 DOWN，持平则等待。
- **与上一场同向买入**：延迟到达后，仅当本场实际入场信号与紧邻上一场的预计 UP/DOWN 一致时买入；不一致或缺少有效预测时，在入场窗口内继续检查，超过截止时间跳过本场。
- **跟随上一场方向**：延迟到达后，直接买紧邻上一场的预计 UP/DOWN，不比较本场方向是否一致，也不要求本场起始参考价已公布。
- **反向买入**：延迟到达后，本场起始价到当前价的方向为 UP 时买 DOWN，为 DOWN 时买 UP；持平、数据不完整或过期时等待。该模式不跟随上一场方向。信号栏展示取反后的实际买入方向，订单保留原始起始价、行情价及 `current_round_reverse` 规则；历史反转标记按取反后的买入方向与最终结果比较，原始行情和已存信号不覆盖。

上一场方向按平台起止价或同源末秒价预测，不等待官方结算，上一场未参与也可计算。全部模式仍需本场市场、有效盘口、可用资金并通过风控，且保留入场截止时间和每场一次限制；设置的延迟是最早允许检查时间，不保证恰好该秒成交。方向模式不改变按上一单预计输赢计算金额的资金序列。跟随模式的历史反转标记比较上一场预计方向与本场官方最终方向，并展示配置的延迟秒数；缺少上一场预测时不推测。

当前场次进度条下方展示最近 20 个已结束场次，时间从左到右由早到近。绿色圆圈代表官方最终 UP，红色代表 DOWN，灰色代表仍待结算或数据待补充。悬停、键盘聚焦或触摸圆点可查看场次、起始金额、终止金额及变动金额。这里的金额指 BTC/USD 参考价格，读取 Polymarket 事件元数据或下述同源末秒预测；不会用 Binance 价格替代。接口价格与有效预测均缺失时显示“待公布”。历史结果独立于本账户是否参与交易，每 15 秒检查更新，已确认结果缓存在本地服务内存中。

历史浮层在接口终止价缺失时，使用该场最后一秒内最后一个同源、同 TWAP 窗口报价展示“终止金额（预测）”、变动与预计方向，标注采样来源和秒级时间。接口提供 `finalPrice` 后自动覆盖展示金额；价格公布本身不代表官方已结算，圆圈仍以官方兑付结果着色。浮层保留末秒预测记录，与接口价格方向、之后的官方结果分别核对，不一致时明确提示。预测从 SQLite 已归档的起始价、信号元数据和末秒报价读取；没有有效依据时继续显示待公布，不借用其他时段价格，也不覆盖策略已采用的资金序列预测。

反转场次使用更大圆点、金色外环和回转箭头，圆点内的绿/红仍表示最终 UP/DOWN。反转按当前模拟盘/实盘配置的**入场时间**采样的策略信号与官方最终方向比较，以本场官方起始价为参考。例如设置 10 秒，取开盘第 10 秒起首个有效报价，最多允许 5 秒采样延迟，浮层显示目标秒数和实际采样时间。修改入场时间后，会用已保存的 Polymarket 同源原始报价重新计算历史标记，不沿用第 5 秒的信号。不同目标秒数分别缓存在 SQLite，服务独立于策略启停记录信号；缺少对应时刻数据、初始持平、未结算或非二元兑付时不推测反转。已成交订单的原始记录不变；未参与的反转场次不计入账户亏损。

每场额外固定保存第 **5、10、15、20、35、40、45、50、55、60 秒**的实际价格、起始参考价、方向和采样时间。当前入场配置不在这组时也会额外记录。程序暂停交易时仍然采样，历史场次可从 SQLite 保留的原始报价补算，缺失时不填造价格。

## 模拟盘

- 使用真实 CLOB 卖盘逐档估算成交，读取市场费率与指数计算 taker 手续费。
- 同时检查深度、滑点、每份最高买价及最小订单金额。无法按预算完整成交时不创建模拟成交。
- 参考公式：`每份手续费 = rate × (price × (1 - price)) ^ exponent`。预算包含名义金额与手续费。
- 默认模拟资金 1,000 pUSD。高级设置内修改初始资金后，暂停且没有未结订单时点击交易记录右上角“重置模拟资金”才能生效。
- 重置保留历史订单及本场去重记录，开始新的统计会话。
- BTC 曲线从服务启动时开始采集，保留最近两小时；支持查看本场或近 30 分钟，不生成演示价格。

模拟盘只是按订单簿快照的估算，不能保证真实订单同样成交，也不复现撮合延迟和其他交易者争抢流动性。

## 实盘配置

仅在你自己的电脑编辑 `.env`，不要将私钥发送到聊天或填写到网页：

```dotenv
POLYMARKET_PRIVATE_KEY=0x你的签名私钥
POLYMARKET_WALLET_ADDRESS=0x你的Polymarket交易钱包地址
LIVE_TRADING_ENABLED=true
```

钱包地址应为实际 Polymarket 账户的交易钱包，签名私钥应有该钱包的相应权限。按官方 SDK 支持的账户类型工作。需要事先完成账户开通、Polygon/pUSD 资金准备与交易授权。

重启服务后，在实盘页面点击“连接交易钱包”，读取实际余额，再确认当前参数并主动启动。

- 订单先由 `createMarketOrder` 签名，再通过 `postOrder` 单次发送 **FOK**，携带 `maxSpend` 与 `maxPrice`。
- 没有使用会自动发起无限额度授权和补单重试的 SDK 高层 `placeMarketOrder`。程序**不自动做链上交易授权**。
- 只有官方成交记录到达 `CONFIRMED` 才作为实际持仓入账；接受回执不等于已成交。
- 网络超时后不重新发送订单。策略保持运行并持续核对，成交结果确认前不新增买入；可在交易记录展开详情填写官方订单 ID，系统只读核对相同市场与资产的官方成交记录。
- 如果平台没有任何订单、且没有可提供的订单 ID，不会凭余额变化推断“没有成交”；保持运行和核对状态，成交未确认前不新增买入，需人工核实本地记录。不要在未核实前清除数据库。
- 实盘净盈亏按确认成交与市场费率估算，**手续费是估算值**；钱包可用余额直接读取平台，每 15 秒刷新，不把尚未领取的赢单份额当作可用余额。
- **本版本不自动赎回赢单份额**。需要在 Polymarket 领取收益后，余额才能继续用于下单。实盘页面提供直达市场链接。
- 若 FOK 未成交且官方订单状态明确取消/失效，则记为未成交，本场不重发，下一场继续；不视作策略失利，不翻倍。

## 参数与限制

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| 首笔投入 | 10 pUSD | 获胜后恢复的基础投入 |
| 单笔上限 | 320 pUSD | 下一笔翻倍金额超过此值时，恢复首笔并开始新轮，继续策略；等于上限仍可买入 |
| 最大加倍次数 | 6 | 超出可配置序列时跳过本次买入，策略保持运行并持续检查 |
| 累计亏损上限 | 500 pUSD | 风控净盈亏减下一笔预算若突破此线，跳过本次买入，持续检查 |
| 入场延迟 | 开盘后 5 秒 | 首次尝试入场时间 |
| 入场截止 | 开盘后 45 秒 | 晚启动或平台起止价未及时公布时跳过；本场拦截原因写入日志 |
| 与上一场同向 | 关闭 | 开启后，本场实际入场信号须与上一场预计涨跌方向一致 |
| 最大滑点 | 卖一价格的 2% | 与最高买价共同限制订单价格 |
| 每份最高买价 | 0.85 pUSD | 避免在过高价格入场 |

参数在“策略设置”内修改，须先暂停并结清已有订单。修改参数保留连败次数。设置中的“本轮已实现盈亏”统计当前未获胜的连续序列，获胜后开始新一轮并归零；账户累计净盈亏持续保留。

例如首笔 5、单笔上限 32，连续失利时投入为 **5 → 10 → 20 → 5 → 10 → 20…**。金额超限会结束当前加倍轮次，连败级数和本轮盈亏归零并进入新轮，已发生的亏损仍保留在账户累计盈亏和订单中，不返还余额。预计结果推进与官方结算使用同一复位规则，结果晚到不会重复复位。最大加倍次数、累计止损和余额不足仍按原规则暂停；最大加倍次数若先触发或与金额上限同时触发，仍保留暂停行为。官方结算延迟本身不阻塞下一场，但起止价缺失、实际成交未确认、可用余额不足仍会等待或跳过。

## 数据保存与检查

`data/trading.sqlite` 按独立字段、独立表保存账户、配置版本、重置前的会话、交易记录、订单状态变更、下单盘口、早期信号、价格采样、拦截原因、日志和历史场次结果，不再整段存 JSON。交易记录显示下单时间和最终结算时间，导出也包含两者。完整结构和查询示例见 [数据库说明](docs/database.md)，建表定义见 [schema.sql](server/schema.sql)。

旧库首次升级会自动生成 `data/trading.sqlite.pre-v1-时间戳.sqlite` 备份，并在事务内迁移。价格采样和日志不再因页面展示范围而删除；已经被旧版本清理的数据无法恢复。价格记录按来源隔离，旧 Binance 数据不会混入 Polymarket 曲线。`.env`、数据库与依赖目录已在 `.gitignore` 中排除。请自行备份数据库；不要在策略运行中删除。启动新的服务进程会主动暂停策略，但保留此前序列和待结订单。

```powershell
npm.cmd run doctor   # 只读检查 Polymarket 的 Chainlink/TWAP 流、当前市场与双边盘口，不连接钱包
npm.cmd run check    # 服务端语法检查
npm.cmd test         # 策略、模拟成交、持久化、接口校验与实盘保护测试
npm.cmd run build    # 前端生产构建
```

`GET /api/health` 可检测服务健康。状态与事件接口都只允许本机 Host。写接口同时校验同源 Origin 与内存控制令牌，前端自动处理，不提供开放的跨域交易 API。

交易记录与日志通过独立分页接口动态读取，默认每页 20 条，可切换 10/20/50 条；支持上下翻页和刷新。实时推送不携带历史列表，只有记录发生变化时才更新当前选中的页。最近 20 场的圆圈可点击，在新标签页打开对应 Polymarket 场次，悬停仍显示价格与反转详情。

模拟盘的交易记录和运行日志标签中，“导出”右侧各有“清空”按钮。确认后，交易清空会删除所有已结束模拟订单及关联详情，保留待处理订单、每场一次的买入占用、账户余额/累计盈亏/资金序列；日志清空只清除模拟盘历史可见日志，实盘日志不受影响，后续新日志正常显示。清空后列表返回首页。两个标签均支持完整 CSV 导出，导出范围不受当前分页页数限制。

## 重要边界

价格与入场信号均读取 Polymarket 的 Chainlink 价格流，TWAP 窗口按当前场次 cryptoMarketConfig 选择（当前 BTC 5 分钟场次为 60 秒）。场次起始价读取官方事件元数据，缺失时读取 Polymarket 网站价格接口。公开 RTDS 是官方已公布迁移计划的旧协议；本次已实测 TWAP 频道仍可用。若该频道停用或过期，程序停止生成信号，不切回 Binance。最终结果仍严格使用 Polymarket 官方兑付数据，实时价格不能提前保证最终胜负。

买入 0.70 的份额，获胜时每份兑付 1，实际利润并不是本金翻倍。连续亏损后即使下一场获胜，也可能未回本，手续费还会减少收益。马丁策略不能保证盈利。

本次验证已成功只读连接真实行情、订单簿及历史官方结算；未配置真实钱包，因此未发送真实交易。浏览器自动验收因本机无法可靠识别当前网址而停止，前端已完成生产构建与 HTTP 路由检查，尚未完成视觉验收。

官方参考：[TypeScript SDK](https://docs.polymarket.com/getting-started/typescript)、[订单流程](https://docs.polymarket.com/trading/quickstart)、[市场与手续费参数](https://docs.polymarket.com/market-data/market-details)、[手续费](https://docs.polymarket.com/trading/fees)。

**收盘报价追溯预测**：起止价接口尚未返回且末秒没有采样时，向前查找 Polymarket 同预言机窗口中、严格早于该场收盘的最近有效报价；不再限定最后 1 秒。允许追溯至更早场次，保存原始采样时间，在日志与详情标明距收盘秒数，来源标记为追溯预测。下单检查可立即补齐预测并延续马丁序列；后续取得更近采样或官方起止价时更新追溯预测，已发出的订单不重复提交，真实盈亏仍由官方结算。

**蓝色区域恢复确认**：边界暂停后，默认连续 2 个已结束场次收盘严格位于当前入场参考区间的蓝色区域、且当前价格仍在中部才恢复，确认场数可配置 1–48。仅统计暂停后的连续场次，缺失、作废或收盘落在边界均中断计数；方向仍为下侧返回 UP、上侧返回 DOWN。进度和依据保存 SQLite，历史价格更正后重新核对。
**触发价与成交上限分开**：有效卖一必须 <0.50 才触发；成交价允许因滑点上升，默认硬上限 0.55（可配置 0.50–0.99，含上限，按 tick 向下取整）。该策略不再使用相对滑点百分比限制，模拟成交逐档检查深度，实盘使用同一硬限价提交 FOK。

**交易记录隐藏**：交易记录和日志标签各自提供“隐藏”：把当前模式、当前标签已有记录持久化标记为隐藏（不受分页或状态筛选限制），新记录继续显示；“恢复显示”取消该标签的隐藏标记。隐藏不删除记录，不影响待结算订单、每场一次限制、资金序列、报表和完整 CSV 导出。各模拟页面、实盘和日志独立处理，不再使用浏览器隐藏偏好。
