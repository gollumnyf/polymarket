# 页面请求性能（2026-11-25）

## 慢请求诊断

用户报告三连亏跟随订单分页约3.77秒，并出现约3.47秒后取消的请求。修复前本地重复测量，该接口通常3–15毫秒，SQLite分页约1.4–1.6毫秒（冷读约13.5毫秒）；不能把浏览器显示的秒级总耗时等同于数据库耗时。

旧页面各开两条永久SSE：策略状态和独立图表。用每源6条HTTP连接的客户端模拟三个页面后，分页请求无法获得连接；350毫秒后释放一条SSE，分页约4毫秒即完成。由此确认连接池排队可以复现症状，排队时再被历史版本更新取消，会延长界面等待。未对用户截图采集完整HAR，不能据此排除所有网络或系统负载因素。

## 实现

本次修复仅调整展示连接和分页刷新，未改变策略方向判断、马丁资金规则、入场时间及条件、盘口校验、订单提交或成交核对。隐藏页面不停止交易；行情生产与策略快照仍彼此独立。部署前核对实盘未运行且无待处理订单，仅恢复部署前正在运行的模拟盘。

- `GET {本盘}/api/events?chart=1` 同一连接发送默认状态消息、具名 `chart-prices`、`chart-history`、`chart-opening`、`chart-range`。行情直接监听共享价格源，不等待策略更新。初次及重连回放已有行情、target及上下界。各盘账本仍隔离，超出不下单盘保留独立上下界。
- 隐藏/离开标签页释放连接，返回时重连及读取状态；隐藏时暂停历史圆点轮询。关闭界面连接不暂停服务器策略。
- 交易记录和日志：同一个分页查询的版本变化合并刷新，不中断在途查询；完成后查询最新版本。分页、筛选、模式变更及卸载仍取消旧请求，防止串数据。
- 旧状态SSE和图表SSE接口保留兼容。发布后需刷新所有旧交易标签页，旧脚本不会自行减少连接。
- 分页响应 `Server-Timing: db;dur=...;desc="SQLite pagination"` 记录SQL查询和行转换耗时，单位毫秒；不包括客户端排队、传输及主线程渲染。

## 验证

`tests/ui-stream.test.mjs` 覆盖可见页单连接、隐藏释放、返回重连、旧事件隔离、版本刷新合并、行情独立推送、断开清理及三个页面持续连接时分页可返回。`tests/api.test.mjs` 继续验证旧接口及模拟/实盘共享行情回放。测试使用内存账本与假行情，不启动实盘。

本次执行 `node --test --test-isolation=none tests/*.test.mjs` 共450项全部通过，包含原策略、资金、入场及成交处理回归；`npm run build` 通过。

部署后在实际3100服务上保持三个页面的合并SSE连接，同时重复请求三连亏订单分页：五次总耗时17.18、3.92、2.39、2.38、2.61毫秒，对应SQLite耗时6.92、2.46、1.25、1.25、1.49毫秒。此为本机HTTP连接池复测，不替代用户浏览器完整Timing测量。部署前运行的上场方向、三连亏跟随、超出不下单模拟已恢复；布林模拟及实盘保持暂停。

排查时同时看开发者工具Timing的Queueing/Stalled、Waiting/TTFB及响应Server-Timing；如SQL仅数毫秒而总耗时数秒，优先检查连接排队和浏览器负载，再查同期服务事件循环及上游状态。新后台任务仍须遵守开盘保护，不能加入策略判断或下单等待链。
