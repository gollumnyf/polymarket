# Pulse BTC 5M 项目交接文档

本项目是 Windows 本机运行的 Polymarket BTC 五分钟 UP/DOWN 控制台。文档描述代码行为；实时配置和运行状态以对应页面 API 和 SQLite 为准。接手时先看本文件、仓库根目录的 AGENTS.md、git status 和相关测试。

## 架构与入口

| 层 | 入口及职责 |
| --- | --- |
| 前端 | React 19 + Vite 6。src/main.jsx 接收 SSE 快照并按路由挂载页面；src/api.mjs 处理本地接口。样式在 src/styles.css。 |
| 服务 | Node.js >= 24.5、Express、ESM。server/index.mjs 绑定本机 127.0.0.1，默认 3100，创建独立模拟和实盘引擎。 |
| 执行 | server/previous-direction-engine.mjs 实现上场方向策略；server/engine.mjs 管理入场、订单去重、资金、预测、结算；server/strategy.mjs 计算盘口深度与手续费。 |
| 交易所 | server/polymarket.mjs 对接 Polymarket SDK、市场、盘口、认证、下单和余额；server/price-feed.mjs 管理官方 Chainlink 流。 |
| 后台 | server/history.mjs 补齐历史；server/redemption.mjs 处理实盘自动兑换；保留的区间引擎为共享图表提供支撑/压力参考。 |
| 数据 | 内置 node:sqlite，WAL 模式。server/store.mjs、server/schema.sql 定义业务表和迁移；server/reports.mjs 用 SQL 汇总。 |

| 页面 | 本地路径 | 数据库 |
| --- | --- | --- |
| 上场方向模拟 | /previous | data/previous-direction.sqlite |
| 上场方向实盘 | /previous-live | data/previous-direction-live.sqlite |
| 模拟盘报表 | /reports | 模拟盘数据库 |
| 实盘报表 | /live-reports | 实盘数据库 |

页面 API 在 /previous/api 和 /previous-live/api 下，按 paper、live 分开。跟单观察盘、区间突破交易、行情领先与配对、GAM 已下线；旧数据库按归档保留。/range 和 /live 页面分别引导到当前模拟、实盘页面，旧交易接口不再启用。旧区间规则见 [归档](research/legacy-range-rules.md)。

## 下单优先级

1. 任一策略运行时，开盘前 12 秒及开盘后 0–15 秒进入保护时段。服务优先调度正在运行的模拟、实盘引擎。开盘前预取下一场市场信息，不再为即将结束的场次发起新的盘口请求。
2. 开盘后并行核对市场接单状态及获取新盘口；仅在当前场次、条件 ID 和各方向代币一致时复用预取结果。预取失败则按市场、盘口的正常顺序请求，绝不使用上一场盘口。
3. 入场优先处理上一场结果与必要的预测、盘口、风险和实盘可用余额。上一笔实盘成交未确认会阻止下一单，因此成交核对属于执行依赖。无须等待最终结算，但有未结订单时必须有可靠预测才能推算资金序列。
4. 历史补拉、旧订单最终结算、展示余额和兑换等不会出现在下单等待链。保护时段暂停发起这些后台请求，历史接口只读现有数据；当前 BTC 参考价的常规 HTTP 刷新也让路。K 线报价复用现有 Polymarket WebSocket；target 由两盘共用的限时只读查询异步提供，不加入下单等待链。后台不能取消已经发送的请求；交易所响应和本机调度仍会影响实际延迟。
5. 兑换还避开下一场开盘前 30 秒，提交前再检查。无明确确认的交易不会假定到账或重复提交。低优先级任务恢复后自动续跑。

## 策略与执行

- 两盘固定反买紧邻上一场：UP 买 DOWN，DOWN 买 UP；刚形成连续两场同向时跳过紧接的一场，之后恢复反向入场检查；同一段连续走势只跳过一次。按紧邻市场结果计数，不以是否成交为准；反向、作废或缺失打断连续计数。
- 官方结果优先；未结算可用 Polymarket 起止价或同源末秒/收盘前最后一笔预测。无有效方向或官方作废的上一场不可用，不跳场选更早结果。最近 40 场同反向比较只供参考。
- 开盘 0–15 秒入场，每场最多一次。检查所选方向卖一价在各自可配置的范围内（默认 0.40–0.70，包含两端），按 tick、深度、手续费和最小份额检查；订单各档成交价受上限约束。实盘的最低价是下单触发条件。
- 马丁规则：从首笔金额开始，预计失利加倍，预计获胜回首笔；超过单笔上限或最大加倍次数从首笔开始。余额、止损和待确认状态会限制新单。后续以官方结算核对并记录差异。配置、资金序列、日志与订单分别保存；页面启动时使用最新输入的首笔金额。
- 模拟按真实盘口逐档估算成交。实盘使用 Polymarket CLOB 提交一笔 FOK，只有官方成交确认才记入持仓。成交核对按订单 ID 匹配官方账户成交，兼容 CONFIRMED 和 TRADE_STATUS_CONFIRMED；MINED 和其他未最终确认状态继续等待。提交超时进入待核对，不能重发；可从交易记录补填官方订单 ID。程序不自动做链上授权。
- 账户认证依赖 .env 的 POLYMARKET_PRIVATE_KEY、POLYMARKET_WALLET_ADDRESS 和 LIVE_TRADING_ENABLED。SDK 派生 CLOB 凭据；刷新实盘页会通过本机受控接口自动尝试连接 Polymarket；配置缺失则跳过，已认证复用连接，开盘保护时段延后。连接不启动策略。钱包面板可手动重读配置和余额，无需重启。有待结订单或策略正在运行时禁止切换钱包。
- 自动兑换仅处理由当前功能记录了所属钱包且已官方结算、有兑付的本程序订单。填写 .env 的 POLYMARKET_RELAYER_API_KEY 和 POLYMARKET_RELAYER_SIGNER_ADDRESS，再刷新钱包。链上确认后刷新余额；提交不明需人工核对。历史盈亏以结算时间归属，兑换到账并不重复计入盈亏。没有真实链路的测试结果时，不把模拟测试表述为已实测成交/兑换。

## 页面与数据

- 模拟盘、实盘和区间参考后台复用同一条 Polymarket Chainlink WebSocket；各行情消费者独立读取报价增量，交易状态、配置、订单和账本继续分开。两盘图表统一订阅 `/api/chart-events`，先回放共享行情库与内存的近 30 分钟报价，再接收增量报价、当场官方 target 和支撑／压力区间。交易状态 SSE 不重复发送图表报价；图表不等待策略轮询，也不进入下单等待链。
- 本场视图开盘最多给官方 target 预留 2 秒；期间 target 已到可与首点同时画出，超时则先画本场实时点，收到官方起始价后补线。若先收到本场开盘边界（时间戳恰等于开盘时刻）的同口径官方流报价，立即画「target · 待核对」，不以附近报价替代；官方起始价到达后覆盖。策略已读取的当场官方起始价也可发布到共享图表。暂定线仅供展示，不计算本场涨跌，不参与交易或预测。近 30 分钟视图不等待。target 首次读取官方事件 priceToBeat，缺失时读取同口径官方 crypto-price 的 openPrice；已知口径时并行重试这两个官方来源。图表有订阅者时共享报价连接可独立重连。每次连接有独立的 15 秒接收窗口；过期缓存和心跳不会重置此窗口或反复关闭刚建的连接。共享区间只用于图表，开盘保护期间停算；本场未就绪时，两盘均可沿用紧邻上一场同口径的支撑位、压力位和底色，标明来源。本场结果到达后一起更新；预言机口径变化或跨过一场时不沿用。
- 历史列表为 41 场已结束市场 + 当前场。绿 UP、红 DOWN、灰待定；当前场实时预估有虚线圈，上一场预测有红色图钉，官方结果更新后去掉。两盘已成交且预计失利时，本场虚线圈变成反转黄，上一场的待结算预测加黄色反转实线圈并保留红钉。统计只计官方结果。圆点支持悬浮详情和 Polymarket 深链接，模拟盘和实盘都用同样的 B 标记标出各自已成交的场次；待确认、未成交及拒单不标。
- 历史接口先返回 SQLite 记录，缺失/未结算由后台补拉。同源价格、起始价、预测、入场快照、拦截依据分别存储，已确认数据不因切换场次或接口异常消失。
- 交易记录和日志从 SQLite 分页，支持首页/末页、条件筛选、展开下单原因、导出，以及隐藏旧记录而不删除数据。新记录仍正常显示。模拟资金重置有独立入口。
- 模拟/实盘报表各自显示日历与区间汇总，默认近 30 天，按北京时间 00:00 切日。支出、下单量和买入手续费按下单日；已实现盈亏、胜负按结算日。报表读取包括隐藏的历史订单。
- SQLite 以场次开盘 Unix 秒为键；采样和事件时间为 Unix 毫秒。金额用 pUSD，盘口份额价格小于 1。明细表和迁移规则见 [数据库文档](database.md)。

## 运行与维护

- 安装依赖：npm ci；开发模式：npm run dev；生产模式：npm run build，然后 npm start。Windows 日常使用仓库启动/停止批处理，后台日志在 data/server-out.log 和 data/server-error.log。
- 校验：npm run check、npm test、npm run build。执行规则的测试用固定时间和假的交易所接口；验证不得提交真实订单或启动实盘。
- 修改运行中的服务前先核对实盘状态。未要求暂停正在运行的实盘时不要为了部署而中断；服务重启后不自动恢复实盘。数据库、私钥、API 凭据不进入 Git 和日志输出。
- 复用现有组件与 ESM 风格。历史订单原因和原始证据不得用现在的策略重写。避免为轻量修改引入新框架。
- **每次改变功能、策略、API、数据库、配置或运维流程，在同一次改动同步更新本文件和相关专项文档。** 更新入口和用户操作可同时改 README。陈旧规则移到归档并注明与运行版本的区别。
