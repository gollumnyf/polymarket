# Pulse BTC 5M 项目交接文档

本项目是 Windows 本机运行的 Polymarket BTC 五分钟 UP/DOWN 控制台。文档描述代码行为；实时配置和运行状态以对应页面 API 和 SQLite 为准。接手时先看本文件、仓库根目录的 AGENTS.md、git status 和相关测试。

## 架构与入口

| 层 | 入口及职责 |
| --- | --- |
| 前端 | React 19 + Vite 6。src/main.jsx 接收 SSE 快照并按路由挂载页面；src/api.mjs 处理本地接口。样式在 src/styles.css。 |
| 服务 | Node.js >= 24.5、Express、ESM。server/index.mjs 绑定本机 127.0.0.1，默认 3100，创建独立模拟和实盘引擎。 |
| 执行 | server/previous-direction-engine.mjs 实现上场方向策略；server/engine.mjs 管理入场、订单去重、资金、预测、结算；server/strategy.mjs 计算盘口深度与手续费。 |
| 交易所 | server/polymarket.mjs 对接 Polymarket SDK、市场、盘口、认证、下单和余额；server/price-feed.mjs 管理官方 Chainlink 流。 |
| 后台 | server/history.mjs 补齐历史；server/redemption.mjs 处理实盘自动兑换；保留的区间引擎为共享图表提供支撑/压力参考。 |
| 数据 | 内置 node:sqlite，WAL 模式。server/store.mjs、server/schema.sql 定义业务表和迁移；server/reports.mjs 用 SQL 汇总。 |

## 下单优先级

1. 任一策略运行时，开盘前 12 秒及开盘后 0–15 秒进入保护时段。服务优先调度正在运行的模拟、实盘引擎。开盘前预取下一场市场信息，不再为即将结束的场次发起新的盘口请求。
2. 开盘后并行核对市场接单状态及获取新盘口；仅在当前场次、条件 ID 和各方向代币一致时复用预取结果。预取失败则按市场、盘口的正常顺序请求，绝不使用上一场盘口。
3. 入场优先处理上一场结果与必要的预测、盘口、风险和实盘可用余额。上一笔实盘成交未确认会阻止下一单，因此成交核对属于执行依赖。无须等待最终结算，但有未结订单时必须有可靠预测才能推算资金序列。
4. 历史补拉、旧订单最终结算、展示余额和兑换等不会出现在下单等待链。保护时段暂停发起这些后台请求，历史接口只读现有数据；当前 BTC 参考价的常规 HTTP 刷新也让路。K 线报价复用现有 Polymarket WebSocket；target 由两盘共用的限时只读查询异步提供，不加入下单等待链。后台不能取消已经发送的请求；交易所响应和本机调度仍会影响实际延迟。
5. 兑换还避开下一场开盘前 30 秒，提交前再检查。无明确确认的交易不会假定到账或重复提交。低优先级任务恢复后自动续跑。

## 策略与执行

- 两盘固定反买紧邻上一场：UP 买 DOWN，DOWN 买 UP；刚形成连续两场同向时跳过紧接的一场，之后恢复反向入场检查；同一段连续走势只跳过一次。按紧邻市场结果计数，不以是否成交为准；反向、作废或缺失打断连续计数。
- 官方结果优先；未结算可用 Polymarket 起止价或同源末秒/收盘前最后一笔预测。无有效方向或官方作废的上一场不可用，不跳场选更早结果。最近 40 场同反向比较只供参考。
- 开盘 0–15 秒入场，每场最多一次。检查所选方向卖一价在各自可配置的范围内（默认 0.40–0.70，包含两端），按 tick、深度、手续费和最小份额检查；订单各档成交价受上限约束。实盘的最低价是下单触发条件。
- 马丁规则：从首笔金额开始，预计失利加倍，预计获胜回首笔；超过单笔上限或最大加倍次数从首笔开始。余额、止损和待确认状态会限制新单。后续以官方结算核对并记录差异。配置、资金序列、日志与订单分别保存；页面启动时使用最新输入的首笔金额。
- 模拟按真实盘口逐档估算成交。实盘使用 Polymarket CLOB 提交一笔 FOK，只有官方成交确认才记入持仓。成交核对按订单 ID 匹配官方账户成交，兼容 CONFIRMED 和 TRADE_STATUS_CONFIRMED；MINED 和其他未最终确认状态继续等待。提交超时进入待核对，不能重发；可从交易记录补填官方订单 ID。程序不自动做链上授权。
- 账户认证依赖 .env 的 POLYMARKET_PRIVATE_KEY、POLYMARKET_WALLET_ADDRESS 和 LIVE_TRADING_ENABLED。SDK 派生 CLOB 凭据；刷新实盘页会通过本机受控接口自动尝试连接 Polymarket；配置缺失则跳过，已认证复用连接，开盘保护时段延后。连接不启动策略。钱包面板可手动重读配置和余额，无需重启。有待结订单或策略正在运行时禁止切换钱包。
- 自动兑换仅处理由当前功能记录了所属钱包且已官方结算、有兑付的本程序订单。填写 .env 的 POLYMARKET_RELAYER_API_KEY 和 POLYMARKET_RELAYER_SIGNER_ADDRESS，再刷新钱包。链上确认后刷新余额；提交不明需人工核对。历史盈亏以结算时间归属，兑换到账并不重复计入盈亏。没有真实链路的测试结果时，不把模拟测试表述为已实测成交/兑换。

三连亏跟随模拟（当前 LF-002，旧 LF-001 保留审计）：只监控上场方向模拟当前账户会话中已成交的订单，按订单连续计亏，未下单不打断；作废、获胜或未知打断。开盘前用已有同源报价和官方起始价预判当前单，开盘后只用已结束的来源订单复核，官方结果优先；尚未结算可用同源预测。跟随盘实际成交后沿用来源入场方向、跳场逻辑和价格范围，使用独立模拟资金及马丁参数。LF-002 首笔使用配置金额，失利后下一笔预算＝上一笔预算 × 2 + 5 pUSD；例如首笔 5 时为 5、15、35、75。预计获胜恢复首笔并重新待命，后续核对官方结果；再次触发需要胜单之后来源盘的三笔新失利。超过单笔上限或最大加倍次数恢复首笔，资金不足及累计止损继续限制入场；按预计结果续投、实际下单、拦截诊断、页面下一笔与资金序列共用此金额规则。独立账本和历史，默认暂停；共享行情 WebSocket 和图表配置，不启用实盘。上场方向模拟和实盘继续使用原来的纯翻倍，历史 LF-001 订单金额与版本不改写。

跟随盘离线研究入口为 `node scripts/backtest-loss-follow.mjs`，默认使用当前 LF-002 金额规则，加入 `--legacy-lf001` 可研究旧纯翻倍规则；结果包含策略版本，不把旧 LF-001 利润当作 LF-002 的验证。只读现有来源成交、预测和盘口，复用跟随引擎在内存 SQLite 回放，结果另存 `data/loss-follow-research/<时间戳>/report.json`，不修改或启动运行账户。旧规则的方法、当前来源版本子样本及局限见 [LF-001 2026-11-24 回测](research/LF-001-backtest-2026-11-24.md)；原来源未成交时缺少连续双边盘口，不能将该条件回放宣称为完整实时成交回测。

## 页面与数据

- 页面名称与固定英文唯一标识集中定义于 `src/pages.mjs`，侧栏每个页面菜单的中文名下方显示其ID，菜单DOM同时提供 `data-page-id`。`previous`＝上场方向模拟，`level-limited`＝上场方向震荡区间内模拟，`bollinger`＝上场方向布林模拟，`loss-follow`＝三连亏跟随模拟，`previous-live`＝上场方向实盘，`reports`＝模拟盘报表，`live-reports`＝实盘报表。ID与现有路由同名，后续跨页面关联以ID为准，不依赖可变中文名称；本次更名不迁移API、数据库或历史订单。工具操作另显示 `strategy-settings` / `user-guide`，分别打开当前页设置/指南，不代表独立交易账本。小屏收起文字时可通过菜单悬停标题识别ID。
- 术语「震荡区间」统一指下支撑位至上压力位的完整区间（含两端），中间蓝色区域是其中一个子区域。「上场方向震荡区间内模拟」原名「上场方向（超出不下单）模拟」，策略仍为LP-001，没有改变选向、入场、马丁或下单行为。

- `/level-limited` 是「上场方向震荡区间内模拟」，LP-001 在 PR-001 基础上增加完整支撑—压力区间过滤（含两端），蓝区不限制。`LevelLimitedStore/LevelLimitedEngine` 首次仅复制来源资金及图表参数，不复制账户余额和历史，之后下单配置与支撑压力配置全部独立。`independentLevelRange` 使用共享原始行情与独立设置计算本盘上下界，入场前仅同步做本地必要计算、不等待HTTP；读取共享价格流的本场、同预言机且6秒内新鲜报价，交易前重复核对。越界、报价及区间未就绪会记录确切原因，15秒内恢复后可尝试，未成交不计亏损。`level_limit_order_signals` 保存每单实际区间和价格。`/level-limited/api/chart-events` 共用行情和target，但推送本盘独立上下界；设置要求本盘暂停且无持仓。共享历史补数范围按新盘回看需求扩展，继续避开开盘保护。账户、日志、报表独立，新盘默认暂停。详见 [专用说明](LEVEL_LIMITED.md)。

- 布林线绘图裁剪使用 `src/bollinger.mjs.visibleBollingerBands`：在窗口左边界保留最近一根K线范围内的已知前序指标值作为起点，不丢弃首段，也不把后续收盘值提前。真实缺口及口径切换保持断线，适用于本场和近30分钟视图。

- 上场方向布林模拟 `/bollinger` 复用 PR-001 策略及现有布局，使用 `BollingerStore/BollingerEngine` 和独立账本；首次仅复制上场方向模拟的配置参数，不复制余额、订单或日志，以配置初始余额创建暂停账户。`bollinger_settings` 逐列保存显示开关、周期、标准差倍数、K线时长。默认20根1分钟K线、2倍总体标准差，当前K线实时变化。历史覆盖N根配置K线加31分钟：共享本地5秒桶聚合优先；缺失的已结束K线通过官方 crypto-price 接口读取该桶最后一秒的同口径参考快照，独立保存于 `bollinger_history_prices`，不复制到实时ticks或交易预测。`BollingerHistoryRepair` 最多2并发、按末秒去重、失败退避重试，每次发起前遵守全局开盘保护；配置变化重算缺失，已有缓存复用。`GET /bollinger/api/bollinger-history` 返回现有数据和补齐进度，异步启动补数、不等待上游；保护期返回202。前端补数时2秒刷新、完成后60秒刷新。布林线仅叠加图表，不改变择向、跳场、价格限制和纯翻倍资金规则，暖机不阻塞下单。共用实时行情、target及支撑压力参考，无新增行情WebSocket。详见 [布林模拟](BOLLINGER.md)。

- 模拟盘、实盘和区间参考后台复用同一条 Polymarket Chainlink WebSocket；各行情消费者独立读取报价增量，交易状态、配置、订单和账本继续分开。前端通过本盘 `/api/events?chart=1` 的一条 SSE 同时接收状态及具名的 `chart-prices/history/opening/range` 事件；行情生产独立于策略快照，先回放共享行情库与内存近31分钟报价、官方target及区间，不等待策略轮询或进入下单等待链。`server/ui-stream.mjs` 共用发送及清理逻辑，旧 `/api/events` 及 `/api/chart-events` 保留兼容；超出不下单盘推送本盘独立上下界。
- `src/page-stream.mjs` 在标签页隐藏或离开时释放SSE，重新可见后重连、回放并刷新状态；服务器交易持续运行。历史圆点及布林历史暂停隐藏页轮询。避免多个页面各占两条HTTP/1.1长连接，耗尽同源连接池而拖慢分页及刷新。`src/coalesced-refresh.mjs` 合并同查询的历史版本刷新：在途请求完成后最多补一次最新查询，只有分页/筛选/模式切换或卸载才取消旧查询，防止连续取消造成空等。订单及日志分页响应提供 `Server-Timing: db;dur=...`，用于区分SQLite处理与浏览器排队；诊断及验证见 [页面请求性能](UI_PERFORMANCE.md)。
- 本场视图开盘最多给官方 target 预留 2 秒；期间 target 已到可与首点同时画出，超时则先画本场实时点，收到官方起始价后补线。若先收到本场开盘边界（时间戳恰等于开盘时刻）的同口径官方流报价，立即画「target · 待核对」，不以附近报价替代；官方起始价到达后覆盖。策略已读取的当场官方起始价也可发布到共享图表。暂定线仅供展示，不计算本场涨跌，不参与交易或预测。近 30 分钟视图不等待。target 首次读取官方事件 priceToBeat，缺失时读取同口径官方 crypto-price 的 openPrice；已知口径时并行重试这两个官方来源。图表有订阅者时共享报价连接可独立重连。每次连接有独立的 15 秒接收窗口；过期缓存和心跳不会重置此窗口或反复关闭刚建的连接。共享区间只用于图表；两盘设置中的「支撑位 / 压力位回看时间」共用并持久化，默认 60 分钟，允许 15–1440 分钟（每 5 分钟一档），沿用 5 分钟实体 K 线和原计算滞后。「中间蓝色区域占比」也共用并持久化，通常默认 60%（升级沿用此前图表比例），允许大于 0% 至 100%，剩余宽度在上下两侧均分。开盘保护期间停算；本场未就绪时，两盘均可沿用紧邻上一场同口径的支撑位、压力位和底色，标明来源。本场结果到达后一起更新；预言机口径变化或跨过一场时不沿用。
- 历史列表为 41 场已结束市场 + 当前场。绿 UP、红 DOWN、灰待定；当前场实时预估有虚线圈，上一场预测有红色图钉，官方结果更新后去掉。两盘已成交且预计失利时，本场虚线圈变成反转黄，上一场的待结算预测加黄色反转实线圈并保留红钉。统计只计官方结果。圆点支持悬浮详情和 Polymarket 深链接，模拟盘和实盘都用同样的 B 标记标出各自已成交的场次；待确认、未成交及拒单不标。
- 历史接口先返回 SQLite 记录，缺失/未结算由后台补拉。同源价格、起始价、预测、入场快照、拦截依据分别存储，已确认数据不因切换场次或接口异常消失。
- 交易记录和日志从 SQLite 分页，支持首页/末页、条件筛选、展开下单原因、导出，以及隐藏旧记录而不删除数据。新记录仍正常显示。模拟资金重置有独立入口。
- 模拟/实盘报表各自显示日历与区间汇总，默认近 30 天，按北京时间 00:00 切日。模拟报表提供「上场方向模拟」「三连亏跟随」「上场方向布林模拟」「上场方向震荡区间内模拟」标签，分别读取 `/previous/api/paper/report`、`/loss-follow/api/paper/report`、`/bollinger/api/paper/report`、`/level-limited/api/paper/report`；切换标签保留日期筛选、月份及选中日，取消旧请求，并按接口与日期校验返回数据，避免独立账本串显。日历、每日明细和汇总均属于当前标签。支出、下单量和买入手续费按下单日；已实现盈亏、胜负按结算日。报表读取包括隐藏的历史订单。
- SQLite 以场次开盘 Unix 秒为键；采样和事件时间为 Unix 毫秒。金额用 pUSD，盘口份额价格小于 1。明细表和迁移规则见 [数据库文档](database.md)。

## 运行与维护

- 安装依赖：npm ci；开发模式：npm run dev；生产模式：npm run build，然后 npm start。Windows 日常使用仓库启动/停止批处理，后台日志在 data/server-out.log 和 data/server-error.log。
- 校验：npm run check、npm test、npm run build。执行规则的测试用固定时间和假的交易所接口；验证不得提交真实订单或启动实盘。
- 修改运行中的服务前先核对实盘状态。未要求暂停正在运行的实盘时不要为了部署而中断；服务重启后不自动恢复实盘。数据库、私钥、API 凭据不进入 Git 和日志输出。
- 复用现有组件与 ESM 风格。历史订单原因和原始证据不得用现在的策略重写。避免为轻量修改引入新框架。上场方向的规则变化必须先在 server/strategy-versions.mjs 追加不可改写的版本记录，再切换启用版本；只调整参数时沿用策略版本，由 config_id 区分。模拟和实盘均在下单占用时写入策略版本，结算不改写。
