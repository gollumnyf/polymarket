# 旧区间策略规则（归档）

此文档只记录已退出交易的区间策略。当前入口及规则见 [交接文档](../HANDOFF.md)。

## 5. 区间策略：当前有效规则

### 5.1 默认参数

这些是代码默认值，不是对当前数据库实际配置的承诺。运行中的参数以对应 API 状态及 SQLite 当前配置为准。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `streakReverseEnabled` | true | 是否启用连续同向反买 |
| `streakReverseRounds` | 3 | 本场紧前必须连续同向的场数 |
| `lookbackHours` | 2 | 初次选向的市场 UP/DOWN 统计窗口 |
| `levelLookbackHours` | 4 | 支撑/压力历史窗口 |
| `levelLagMinutes` | 15 | 区间计算向前平移，排除最近 15 分钟 |
| `edgePercent` | 20 | 每一侧边界带占区间宽度百分比 |
| `resumeRounds` | 2 | 边界暂停后恢复需要的连续收盘确认数 |
| `executionMaxPrice` | 0.55 | 常规区间策略滑点后成交硬上限 |
| `breakoutPercent` | 0.1 | 突破距离占参考区间宽度百分比 |
| `breakoutRounds` | 2 | 连续收盘突破确认场数 |
| 区间入场延迟 | 0 秒 | 开盘立即尝试，但仍须满足全部条件 |
| 区间入场检测窗口 | 120 秒 | 页面按分钟配置；超时不追单 |

基础 `DEFAULT_CONFIG` 还有旧策略默认值，不要直接把其中 entryDelay/entryWindow/maxPrice 当作 range 的最终值；检查专用引擎和账户配置。

### 5.2 支撑、压力和蓝色区域

1. 采用已结束的 **5 分钟实体 K 线**，实体由官方开盘价、终止价组成，不使用影线最高/最低。
2. 默认使用向前平移 15 分钟后的近 4 小时窗口，共 48 根实体 K 线，取实体最低/最高作为支撑/压力。
3. 每个五分钟场次结束重算；当前未结束场次不会改变自己的历史边界。
4. 不要求往返次数、触及次数、次峰触及门槛或区间最大宽度门槛。
5. 设支撑为 L，压力为 U，每侧比例为 e：蓝色下沿 `L + (U-L)*e/100`，蓝色上沿 `U - (U-L)*e/100`。
6. 入场价格必须严格大于蓝色下沿、严格小于蓝色上沿；等于任一边界不满足。
7. 图表与交易判断必须使用同一组**当前滚动支撑/压力**。`breakoutReferenceLower/Upper` 是突破计数参考线，不能用它计算蓝色区域。

### 5.3 边界暂停与恢复

- 到达边界带或区间外：暂停新单，已有订单继续结算，不关闭策略。
- 返回蓝色区域后，默认需要连续两个已结束场次的收盘价都严格在蓝色区域内；不是要求整场都在区域内。
- 中间缺失、作废、等于边界或收盘在区域外都不能凑成连续确认。
- 只统计符合暂停后恢复条件的已结束场次，下单前再检查当前价仍在蓝色区域。
- 从下支撑侧返回，常规恢复方向买 UP；从上压力侧返回买 DOWN。中部继续沿用这个方向，直到再次触边再按返回侧选向。
- 保留原马丁资金序列，不因为边界暂停而恢复首笔金额。

### 5.4 连续同向反买：禁止回退历史触发

当前开盘场次为 R、配置为 N，只读取：

```text
R - N*300, R - (N-1)*300, ... , R - 300
```

例如本场 10:00、N=3：只能使用 09:45、09:50、09:55 三场。

- 全部 UP → 本场买 DOWN；全部 DOWN → 本场买 UP。
- 不含当前未结束场次；缺一场、作废或方向不同均不触发。
- 未最终结算时允许使用**对应市场场次**的预计结果，官方最终结果随后优先核对。
- 不能跳过缺失场次找更早一场，不能搜索更早的同向片段，也不能因旧事件有效而延续旧反买触发。
- **每个新场次重新检查紧前 N 场**。不满足时回到常规区间逻辑，不代表整个策略停机。
- `range_streak_events` 是审计记录，不是当前选向的回退池。
- 触发后优先选向，但仍须满足蓝色区域、边界恢复确认、每场一单、入场截止和资金限制。
- 该规则下取消策略的 0.50 触发价、0.55 成交硬上限和相对滑点限制；仍检查有效价格、tick、真实深度、最小份额及手续费预算，不能买入价格为 0 或 1 的盘口。
- 报价后及实际提交前需再核对当前条件；不能使用已失效反买规则取得的宽松报价继续下单。

“连续同向反买已启用”是配置说明，不等于本场已触发。实际依据见 `entrySignal.streakSignal`；因蓝色区域被拦截时可能只返回 `lockedStreak` 作为解释依据，不能据此绕过 `code` 或无方向状态。

### 5.5 常规区间选向和突破

- 首次区间选向按近配置小时数内的已结束五分钟市场结果统计多数方向，不统计账户订单盈亏。
- 同票时取紧邻上一场市场结果的反方向；未最终结算可用该场预计结果，不能跳过上一场去找更早结果。
- 区间基础方向保存后沿用，边界返回按上述恢复规则更新方向。
- 突破必须同时满足距离和连续场数，默认距离为参考区间宽度的 0.1%，连续两个已结束场次收盘严格越过同一条线。
- 上穿线：`参考压力 + 参考宽度 * 0.1/100`；下破对称计算。不是 BTC 价格本身的 0.1%。
- 初次越线时固定突破计数的参考上下界，避免每场移动边界吞掉突破；不把多次场内穿越算作多个场次。
- 中断连续性需要重新检查/计数，不能在一个周期内累计不相邻的两次突破。
- 已确认突破仍不能绕过边界暂停。旧突破在回到参考区间或进入新的滚动蓝色区域时按现有状态机退出，已记录的恢复确认要求保留。
- 常规买入要求有效卖一严格 `< 0.50`；触发后可按深度成交至配置硬上限（默认 `<= 0.55`）。不再按相对滑点百分比拦截常规 range。
